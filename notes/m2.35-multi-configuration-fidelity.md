# M2.35 — Multi-Configuration Fidelity

## Scope

M2.35 extends the M2.18 same-realization hypothetical-versus-physical gate
from one final DMV design to a deterministic suite of 26 designs.  It does
not run search, resampling, maintenance calibration, or a fresh sampling
campaign.  Every physical state uses the persisted
`datasets/dmv-frozen-acquisition-sample-v1/sample.copy.bin` and the ordinary
statistics target 100.

The retained M2.17b build-1 payload cache was used because the historical
M2.18 repository directory is no longer present:

```text
payload cache: .build/artifact-cache/dmv-m2-17b-frozen-sample-v1/repository
repository manifest digest: 0698cdb284a2e8e654ac991943cadeb63037319c4ed486a4a4064a2b468e3725
sample semantic SHA256: 59dc8dbe007a81cbd10a11894ff8abf9b4a8f0cac11523221dbd63e34dd4ca7f
sample binary SHA256:   c3b30ddfebf118cb9137bae122e2913e19e88d0cbee14b2c93e980c7693cf463
PostgreSQL: 16.14
```

The cache has the same logical 72-candidate catalog as the prepared
incidence artifact.  Its historical backend OIDs are session-local; the
adapter resolves current shell OIDs by statistics name.  The physical path
checks every native payload against this cache before interpreting estimates.

## Configuration suite

The suite contains empty, MCV and FD singletons, an `ABSENT_NATIVE` singleton,
small/medium/large MCV-only and FD-only designs, mixed designs, same-column
MCV/FD overlap, all 72 candidates, five accepted-trajectory prefixes, the
M2.17d final 31-object design, four deterministic random subsets (seed
20261001), and additional absent/overlap/precedence-sensitive designs.  It
contains 26 unique configurations, including 11 configurations containing the
native-absence candidate.

## Result

All 26 configurations passed all gates:

* hypothetical and physical objectives were exactly equal for 26/26 designs;
* all 1,963 estimate entries and all 1,963 q-error entries matched for every
  design (51,038 query comparisons in total);
* all selected physical payloads matched the frozen repository (396 selected
  payload checks), and each run first rechecked the complete 72-candidate
  physical realization (1,872 payload checks);
* ordinary-statistics digest and relation metadata were equal between paths;
* the empty-design baseline remained 42,791.986480127205 with estimate-vector
  digest `f3254350d068cbd625fffd5537cd25573961da71779977e73811c1d6acb4a93f`;
* the M2.17d final design remained 31 objects (8 MCV, 23 FD), objective
  22,014.061316846422, with exact hypothetical/physical vector equality.

A complete deterministic rerun produced the identical configuration ordering,
configuration suite, semantic per-configuration results, comparison totals,
and summary (excluding diagnostic wall-clock timing).

The complete machine-readable artifact is
`experiments/dmv-m2-35-multi-configuration-fidelity/`; the harness is
`tools/dmv_m2_35_multi_configuration_fidelity.py`.

## Environment provenance and limitation

Before the run, the persistent experiment database had an empty `public.dmv`
relation.  It was restored with the repository's checksum-verified canonical
loader (`scripts/load_dmv_pg16.sh`), yielding 11,591,877 rows.  The compiled
backend did not have the database-local registration for the already compiled
`pg_hypothetical_extstats_register_absent` internal function; that function
was registered in the experiment database, as in the documented M2.21
environment repair.  No PostgreSQL source, patch, binary, candidate catalog,
payload bytes, CE semantics, or search algorithm was changed.

This is evidence of same-realization semantic fidelity across representative
design configurations.  It is not a physical-per-design wall-clock
speedup claim, a robustness study, a new workload, or a claim about future
`ANALYZE` realizations.
