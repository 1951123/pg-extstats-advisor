# M2.14 screened recommendation/deployment/validation smoke

M2.14 validates the end-to-end Census development path introduced in M2.13:

```text
singleton profile -> screened candidate set -> ADD-only search
                  -> recommendation -> deployment -> ANALYZE -> validation -> cleanup
```

This is a development smoke, not a screening-quality study, an authoritative
M2.7 rerun, or an M3 experiment. It reuses the frozen M2.13 recommendation
and does not rerun singleton profiling, acquisition, or search.

The smoke uses deterministic nested prefixes of the M2.13 accepted sequence:
`K=1`, `K=5`, and `K=10`. Candidate identity is resolved from the raw
authoritative catalog, and deployment SQL is generated by the normal
`build_deployment_plan` path. The fixed 468-query workload is evaluated for
both sides of the comparison.

For each prefix, A is the frozen hypothetical evaluation using the acquired
repository. C is a physical deployment followed by fresh PostgreSQL
`ANALYZE` and native `EXPLAIN` evaluation. The existing validation machinery
is reused to compute objective drift, per-query q-error differences, and
payload fingerprints. A/B same-realization control was not run because the
current code has no separate low-cost control path; the protocol therefore
uses the permitted A/C smoke. A/C differences are fresh-statistics
realization drift and are not treated as a CE correctness failure.

`ANALYZE` is forbidden in the search hot path and is performed only in this
validation phase. Each prefix is cleaned before the next one, and the final
catalog check found zero smoke-created statistics. The compact artifacts in
[`experiments/census-m2-14-screened-validation-smoke/`](../experiments/census-m2-14-screened-validation-smoke/)
record recommendation/search/screening lineage, PG build provenance, prefix
designs, DDL, A/C summaries, timing, cleanup, and artifact-size information.
No move-level trajectory or giant per-query validation report is persisted.

The result remains explicitly `development-smoke`; it does not promote the
Census top-5% restriction to a universal policy or resolve the authoritative
M2.7 search.
