# M2.13 formal singleton-screened development workflow

M2.13 turns the previously exploratory Census singleton screen into an
artifact-first development workflow:

```text
prepare -> singleton profile -> deterministic candidate screen
        -> ADD-only search -> recommendation
```

The `singleton-profile` artifact records the frozen workload, raw candidate
catalog, incidence index, payload repository, maintenance model, evaluator
provenance, and the utility of every raw candidate. It can be imported from
an existing frozen singleton CSV without native reevaluation, or generated by
the native evaluator for a new prepared run. The `screened-candidate-set`
artifact records the exact ranking, fraction, rounding rule, retained IDs,
screened-catalog digest, and lineage digests. Both artifacts are validated
before search, and screened search results carry their artifact and profile
digests in `SearchConfig` and recommendation provenance.

The CLI stages are:

```text
pg-extstats-advisor singleton-profile RUN --source-csv frozen.csv --output profile.json
pg-extstats-advisor screen-candidates RUN --singleton-profile profile.json \
    --top-fraction 0.05 --output candidate-set.json
pg-extstats-advisor search RUN --candidate-set candidate-set.json \
    --search-mode add-only --budget-mode candidate-set-total
pg-extstats-advisor recommend RUN
```

`--budget-mode candidate-set-total` assigns the additive maintenance budget
equal to the total cost of the visible screened catalog. This is the frozen
M2.11 development setting, not a universal budget policy. The screening
fraction is always explicit; there is no global five-percent default.

Screening is a development restriction, not a correctness-preserving
replacement for full-catalog optimization. Future benchmarks must create a
singleton profile first, record the screening provenance, and treat the
resulting recommendation as development evidence unless an independent
full-universe comparison is supplied. The workflow does not alter CE
semantics, candidate generation, payload acquisition, or the search
algorithm; it only makes the candidate universe an explicit, validated input.
